# specpowers 单轨瘦身设计（渐进披露 + 定点简化）

- 日期：2026-09-19
- 状态：待用户审阅
- 分支：feat/skill-slimming
- 前置决策（已确认）：
  1. 形态 = **B：单轨瘦身 + 渐进披露**（不做 comet 式双轨，不动 6 技能框架/路由/Gate 链）
  2. 语义边界 = **结构搬运 + 定点简化**（允许简化明显过度的机制，不动判定语义）
  3. S4 = **保留 `[GATE_PASSED]`/`[CONVERGENCE_CHECK]` 全部审计字段**，仅做字段说明去重
- 参考调研：rpamis/comet（同源方法论的双工作流实现）——可借鉴机制为渐进披露（入口 SKILL.md 仅 2.7KB）、防护脚本化、条件加载；本设计取其渐进披露思想，不引入双轨。

## 1. 背景与问题

specpowers 已发布（v1.0.0），正本体量分布：

| 文件 | 行数 | 字节 |
|---|---|---|
| skills/specpowers-review/SKILL.md | 657 | 111.9KB |
| skills/specpowers-review/refs/protocols.md | 777 | 100.9KB |
| skills/specpowers/SKILL.md（入口） | 386 | 26.9KB |
| 其余 4 子技能 SKILL.md 合计 | 628 | 35.5KB |
| skills/*/evals/ 合计 | 737 | — |

review 一家 1434 行占全组正本 60%+。SKILL.md 主体在技能加载时**全文注入上下文**，refs 仅按需 Read——因此「每轮固定成本」由 SKILL.md 行数决定，当前 review 每轮固定吃进 657 行。

模型能力增强后，大量为约束弱模型而写的防护性散文成为纯开销；且正本经多轮评审修复（1252→1434 行）后，同一规则的重复陈述不断累积。

## 2. 诊断：重量从哪来

**不是内容多，是同一规则被完整重述 2–4 遍。** 三种模式：

| 模式 | 实例（现状） |
|---|---|
| 同一规则多点全文重述 | `[拒绝异常]` 判据完整出现在 SKILL.md 6 处（合理化表 393、Red Flags 406、Step 2 检测条 472、Step 3 覆盖规则 488、口径节反偷懒②308、Step 5 遗漏检测 561）+ protocols.md 3 处（协议 3 mode 说明 216、协议 1 注 110 等）；四轴触发面（`p0_raw≥1 ∨ p0_rejected≥1 ∨ agent_rejected≥1 ∨ user_rejected≥1`）散布 5+ 处；条件⑤三差值规则 A/B/C 在 SKILL.md:596 与 protocols.md:108 双份全文 |
| 引用点括号套括号 | 每条规则带 3–5 层嵌套例外（加强审查例外→截断回退→sup3 不占分子→N==0 分叉），例外本身又各自重复（如 SKILL.md:207/211 两段各近千字的加强审查例外散文） |
| 防护散文与执行正文混排 | 合理化表 15 行的「陷阱」列复述 Step 正文、「正确做法」列复述 protocols；Red Flags 清单与多轮防偷懒协议大量重叠 |

估算：review 1434 行中 40–50% 为重复陈述。

另一个结构性事实：渐进披露基础设施**已存在**——SKILL.md 有 32 处 `refs/protocols.md` 引用，父技能与 review 的耦合很薄（每技能 1–3 行标记块检查）。问题只是每个引用点旁边都把规则全文重述了一遍。

## 3. 重构原则

1. **SSOT（单一权威源）**：每条规则只在一处完整定义（判定类规则多数已在「问题数口径权威定义」「P0 阻塞规则」两节）；其余位置一律 ≤1 行短引用（例：`[拒绝异常] 触发 → 见「问题数口径权威定义」反偷懒②；后果 = 无视档位强制 mode=standard`）。**禁止在引用点重述条件**。
2. **按加载触发器分文件**：refs 按「何时需要读」分组，不按主题优雅分组；SKILL.md 主体只留每轮必用的骨架与高频输出格式。
3. **例外集中化**：散布例外收拢到规则权威定义处的「例外表」或所属 refs 文件的例外节；主流程正文只写标准路径。
4. **协议编号是稳定接口**：`协议 1`–`协议 9` 编号跨拆分保持不变（refs 文件内保留「协议 N: 标题」小节头），全仓引用只把 `refs/protocols.md 协议 N` 改为 `refs/<新文件>.md 协议 N`，编号与语义不动——父技能、AGENTS.md、README 的引用面最小化变更。

## 7. 语义不变证明方法（规则唯一性审计）

1. 实施前从正本提取**规则清单**（~25 条规则族：拒绝异常/守恒等式/四轴面/三差值/口径分配/tier 闸门/加强审查例外/退化三要素/…），每条记录「完整定义位置 + 当前全部重述位置」。
2. 每次搬运后对账：每条规则在新结构中**有且仅有一处完整定义**，其余位置均为短引用；grep 每个规则指纹串（如 `> 3 条`、`30%`、`p1_merged > 5`）比对出现处数与性质。
3. evals 全量回归（尤其 MR !4 新增 5 用例：merged-count-convergence / conservation-equation / raw-caliber-step3-deployment / rejected-abnormal-upgrade / reinforced-path-raw-and-trivial-rejection）。
4. 定点简化项（S1/S2/S5、例外表）单独做例外分支矩阵推演 + 有界验证者复核。

## 8. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 渐进披露失败：执行者该读未读 refs，行为退化 | ① 按需加载表用硬指令措辞；② 判定类规则（口径/收敛/路由矩阵摘要/例外表）保留主体，refs 只承载「怎么执行」不承载「判不判」；③ evals 含行为断言回归 |
| 拆分后跨文件漂移（同规则在两份 refs 各改一半） | 规则唯一性审计纳入每 PR 验证；协议编号稳定使引用可 grep 对账 |
| 打包/安装面变化 | refs 文件仍在技能目录内，resourceBase 不变；`verify-dsh-provider` 每 PR 必跑 |
| 例外表格化丢信息 | PR-2 的例外分支矩阵重推演覆盖（加强审查×拒绝异常 N>0/N==0、trivial×被拒项、用户拒 P0 双路径、Step4 退化回退链） |
| 收敛结构缺陷（①–④无跨轮去重） | **不在本设计范围**（已知残留，另立任务）；本设计不改变其行为 |
