# specpowers-review 代码审查分支判定逻辑优化

## 概述

将 specpowers-review 的代码类型审查分支从当前的 2 路径（加强审查/UltraReview）+ 微小任务跳过，改为 3 路径级联判定，引入文件数和修改行数的组合条件作为阈值。

**核心变化**：
- 最小变更不再跳过审查，至少走加强审查
- 多模型渐进式审查（原仅文档类）扩展至中等规模代码
- 阈值从单纯文件数变为文件数+行数组合条件

## 目标逻辑

级联判定（按条件 1→2→3 顺序评估，命中即停止）：

| 条件 | 文件数 | 修改总行数 | 审查类型 | 说明 |
|------|--------|-----------|---------|------|
| 条件 1 | ≤2 | ≤100 | 加强审查 | specpowers-apply code-review + specpowers-review 对齐Agent单审 |
| 条件 2 | ≤5 | ≤400 | 多模型渐进式审查 | 3-agent并行 Step 1-5 全流程 |
| 条件 3 | 其他 | 其他 | UltraReview | 5-agent 团队审查 |

**级联示例**：
- 2文件 80行 → 条件1命中 → 加强审查
- 2文件 200行 → 条件1失败（行>100），条件2命中 → 多模型渐进式
- 6文件 300行 → 条件1失败，条件2失败（文件>5）→ UltraReview
- 3文件 500行 → 条件1失败，条件2失败（行>400）→ UltraReview

**修改总行数** = `git diff --stat` additions + deletions，由 specpowers-apply 在调用 specpowers-review 前计算。

    │   ├── 条件 1：文件数 ≤ 2 且 修改总行数 ≤ 100 → 加强审查

### 多模型渐进式章节新增代码类适配（改动 10 的新增内容）

三 Agent 结构不变（结构/落地/对齐），审查对象从文档变为代码时的关注点适配：

| Agent | 文档类关注点 | 代码类关注点 |
|-------|------------|------------|
| 结构审查 Agent | 完整性/冗余/一致性/结构合理性 | 代码架构一致性、模块组织合理性、接口设计一致性 |
| 落地审查 Agent | 可执行性/兼容性/边界/平台差异 | 编译可行性、运行时行为、边界条件处理、依赖完整性 |
| 对齐审查 Agent | 对齐原始需求/设计；错漏项检测 | 逐条对照 plan+specs+design，COVERED/MISSING/DRIFT |

审查流程（Step 1-5）、监督 Agent 交叉验证、修复-校验循环、Quick Review 收尾均与文档类完全一致。

## 关键设计决策

1. **微小任务执行模式保留**：入口技能的微小任务定义（1-3文件, <50行）控制 Phase 0-2 是否跳过，与审查阈值独立。即使微小任务，Phase 3 实现完成后仍走加强审查路径
2. **多模型渐进式用于代码 = 完整 Step 1-5**：与文档类流程完全一致，仅 Agent 关注点从文档适配为代码
3. **级联评估**：条件 1 优先于条件 2，命中即停止
4. **标记块预期**：加强审查 STEP1-STEP2，多模型渐进式和 UltraReview 均为 STEP1-STEP5
5. **旧阈值（≥10文件/<10文件/微小任务跳过）全部替换**，不留残留引用

## 约束条件

- 文档类审查路径不变
- 所有现有协议行为保持不变（双层验证、硬阻止、标记块验证、退化声明）
- 跨 Skill 的 grep 匹配模式精确格式不变

## 验证方法

1. 通读修改后的审查决策树，确认 3 路径级联逻辑正确
2. `grep` 搜索 `>=10.*文件\|<10.*文件\|微小任务.*跳过\|微小任务模式` 确认无残留旧引用
3. 确认验证 1 的 STEP 标记预期与各审查类型匹配
4. 确认各模式映射表审查列不再有"跳过"
